ORIN — دليل الاستلام والمتابعة للمبرمج
النسخة المرجعية: 1.6.2 | versionCode: 20 | تاريخ التسليم: 2026-10-06

اقرأ هذا الملف أولًا. هو مرجع التسليم الحالي؛ بعض ملفات README الأقدم تصف إصدارات تاريخية وليست حالة الإنتاج اليوم.

1) ما الذي تستلمه؟
• ORIN-1.6.2-Full-Developer-Package.zip: كامل مصدر Android والواجهة والويب والخادم والإدارة، الأصول البصرية والصوتية والخطوط، مخططات البيانات والترحيلات والقواعد والفهارس، الاختبارات، التقارير، APK الحالي، وبناءا الويب.
• ORIN-Original-Signing-Private.zip: حزمة ZIP مشفرة AES-256، تحتوي مفتاح التوقيع الأصلي PKCS12 وكلمة مروره الأصلية والشهادة ودليل الاستعادة.
• ORIN-Signing-Unlock.txt: كلمة فتح الأرشيف المشفر فقط. يستلمها المبرمج عبر قناة منفصلة؛ لا تنشرها في Git أو الاستضافة. كلمة keystore الأصلية داخل الأرشيف.
• هذا الدليل، وCHECKSUMS-SHA256.txt للتحقق من الملفات.

الحزمة الرئيسية لا تحتاج كلمة مرور. افتح حزمة التوقيع ببرنامج يدعم ZIP AES-256، مثل 7-Zip؛ بعض أدوات فك الضغط الافتراضية لا تدعمه.
لم يُستبدل المفتاح أو تُغيّر كلمة مروره. لا تنشئ keystore جديدًا.

3) الحالة الحقيقية — لا تخلط البناء بالتفعيل
• تم بناء APK والويب الحالي ومرشح الأمان. التوقيع الأصلي محفوظ.
• فحص TypeScript ناجح؛ 12 اختبار تراجع للعميل/الدعم/التوافق ناجحة؛ 29 تحققًا لسياسة القفل وPIN على JVM ناجحة.
• لم يُجرَ اختبار هاتف Android فعلي على هذه النسخة. لا تعتبرها مقبولة نهائيًا قبل اختبار جهاز حقيقي.
• Firebase project: orin-99951. المنطقة المتوقعة للخادم: europe-west1.
• النطاقان في الكود: orin-99951.web.app وorin-99951.firebaseapp.com.
• الحساب في Firebase Console كان مفتوحًا، لكن صفحة Functions طلبت Blaze، ولم يوجد Cloud Billing Account. لم تُربط فوترة ولم تُنشر Functions أو قواعد جديدة أو Hosting في إصدار 1.6.2.
• APK الحالي يحتفظ بمسار الدخول المتوافق مع Spark. لا تعلن أن AI أو الأمان الخادمي أو السحب مفعّلة بسبب وجود واجهتها.
• الذكاء الاصطناعي اجتاز سابقًا اختبارات تطوير مع Gemini وخادم ORIN وبيانات محاكاة معزولة؛ لم يُثبت مسار إنتاج كامل داخل APK.
• بث الدعم الحالي يعرض تقدمًا فعليًا ثم ردًا كاملًا بعد التحقق والحفظ، وليس بث كلمات للمستخدم كلمة بكلمة.
• المدفوعات: يوجد تكامل إيداع NOWPayments في المصدر. السحب الحقيقي غير مفعّل/غير مكتمل، وكذلك تنفيذ صفقات سوق حقيقية والتحويل الحقيقي؛ العقود الحالية داخلية افتراضية. لا تحوّل هذه الحالات إلى «مفعّل» دون تنفيذ واختبار.

4) تشغيل المصدر وبناء نسخة مطابقة
البيئة الأنسب للسكربت الحالي: Linux x86_64 أو WSL2، Node.js 22.13+، Python 3، وJDK 17 كامل لبناء APK. محاكيات Firebase تحتاج Java 21؛ بدّل بيئة Java عند اختبارها ثم ارجع لـ JDK 17 عند البناء. لا تستخدم JRE فقط لبناء التطبيق.

من داخل source:
    npm ci
    npm ci --prefix firebase-functions
    ./node_modules/.bin/tsc --noEmit
    npm run build:firebase-spark
    npm --prefix firebase-functions run build

الناتج firebase-spark-dist هو الذي يضمّه android-app/build.py داخل APK. أمر npm run build العام يخص مسار الويب الآخر، فلا تستبدله بأمر بناء Firebase أعلاه.
للتحقق من مرشح الأمان دون نشره:
    npm run build:firebase-security

إعداد Android SDK الحالي:

  SHA1: 0bb560a90a7a2cbd0dd8348224d518b638fe7949
  فكّه بحيث يوجد .android-build/platform/android-35/android.jar
• build-tools_r35_linux.zip من:
  https://dl.google.com/android/repository/build-tools_r35_linux.zip

هذه النسخ المثبتة هي المستخدمة في البناء السابق، وليست مطالبة باستخدام أحدث SDK مختلف. راجع تراخيص Google للأدوات عند تثبيتها.

6) الحفاظ على التعديلات والهوية
• المرجع الحالي هو المصدر المرفق، لا تعِد بناء ORIN من لقطة شاشة أو من الصفر.
• لا تغيّر إعدادات TradingView عند تعديل بطاقة السعر المصغرة. دليل المقارنة موجود في verification-162/chart-preservation.json.
• لا تستخدم Reload كاملًا للتنقل أو تبديل الحساب. افصل حالة الحساب الحقيقي والتجريبي على مستوى التخزين والخادم.
• لا تعبّئ الأسعار أو الأرصدة أو الإحالات بقيم وهمية لإخفاء فشل اتصال.
• شارت البطاقة يمثل سجلًا تاريخيًا على 24 ساعة بفواصل 15 دقيقة؛ ليس رسمًا اصطناعيًا يتسارع مع كل سعر لحظي.
• لقطات الشاشة مسموحة في الصفحات العادية؛ نافذة PIN الأصلية تظل محمية. لا تُلغِ القفل أو غطاء الخلفية لتصحيح التصوير.
• صحّان في المحادثة يعنيان تأكيد وصول الرسالة للخدمة، وليس قراءتها من موظف. استخدم metadata الفعلية ولا تضع صحّين على رسالة غير مرسلة.

8) Firebase: تسلسل المتابعة الصحيح
أ) يحصل المبرمج على دعوة IAM مناسبة من المالك؛ لا يحتاج كلمة مرور Google الخاصة بالمالك. ينشئ المالك/يربط حساب الفوترة ويفعّل Blaze عند الموافقة على الرسوم.
ب) احتفظ بنسخة من القواعد والفهارس والتهيئة والإصدار المنشور ونسخة بيانات قبل الترحيل. صفحة القواعد وحدها ليست نسخة احتياطية للبيانات.
ج) سجّل Firebase CLI بالطريقة الرسمية وتأكد أن المشروع هو orin-99951. صلاحية API لمزوّد AI ليست صلاحية إدارة Firebase.
د) اقرأ أولًا ADAM-DEPLOYMENT-161.md وSECURITY-DEPLOYMENT-160.md وfirebase-functions/ACCOUNT-SECURITY.md وSUPPORT-AI.md. هذا الدليل الحالي يوضح النقاط التي تغيّرت بعدها، ومنها موفر Gemini وعدم اكتمال الفوترة.
هـ) ابدأ بمشروع اختبار منفصل. راجع firebase.security-161.json وقواعد firebase-security-160.rules والفهارس firebase-security-161.indexes.json. احتفظ بقيمة rulesVersion:160؛ ليست رقم إصدار التطبيق.
و) خزّن أسرار الخادم في Secret Manager، ولا تضعها في VITE_* أو APK أو ملفات المصدر. أُرفقت قوالب أسماء المتغيرات فقط.
ز) راجع فجوة MFA على مستوى Firebase Auth نفسه قبل ادعاء حماية كاملة: TOTP الخاص بـ ORIN لا يمنع وحده مسارات تغيير الحساب المباشرة لدى مزود الهوية. كذلك سجل فشل كلمة المرور لدى المزود يحتاج تكاملًا فعليًا. لا تُحل هاتان النقطتان بمجرد Blaze.
ح) نسّق نشر الخادم والقواعد والعميل وتفعيل المستند system/account-security بعد التحقق. نشر القواعد الصارمة أولًا على العملاء الحاليين قد يمنع دخولهم. لا تنفذ firebase deploy شاملًا عشوائيًا أو تستخدم إعدادات قديمة دون مراجعة.
ط) اختبر المسار الكامل الحقيقي: App → Backend → AI Provider → حفظ الرد → عرضه؛ ثم العزل بين مستخدمين والتصعيد وانقطاع الخدمة وإبطال الجلسات. بعد ذلك فقط أنشئ APK مرتبطًا بالخادم الذي اختُبر.
ي) build.py يقرأ firebase-spark-dist تحديدًا. إذا قرر المبرمج اعتماد أصول مرشح الأمان داخل APK، يجب تجهيز تلك الأصول في مسار الإدخال المقصود بعد اختبارها، والتحقق من VITE_ORIN_SECURITY_API_URL وPROGRAM_API_URL. تشغيل build:firebase-security وحده لا يبدّل ما يدخل APK.

9) الأسرار والخدمات الناقصة
الموجود في التسليم هو مفتاح توقيع Android الأصلي وكلمة مروره، ضمن الحزمة الخاصة فقط.
لا توجد حزمة صلاحيات Google IAM/Service Account أو كلمة مرور مسؤول جديدة يمكن اختلاقها. لا توجد نسخة من أسرار عملاء TOTP أو كلمات مرورهم.
المفتاح التجريبي السابق للذكاء الاصطناعي كان مكشوفًا في المحادثة ولم يُضمّن في المصدر أو APK؛ لم يُلغَ من المزوّد. اطلب من المالك مفتاح Production جديدًا عبر وسيلة آمنة قبل نشر الخدمة للمستخدمين، وألغِ التجريبي بعد اختباره حسب اتفاق المالك.
ORIN_SECURITY_MASTER_KEY: يولَّد مرة واحدة على الخادم كـ32 بايت عشوائية بصيغة Base64؛ لا تدوّره بلا خطة ترحيل لتشفير TOTP.
ORIN_SUPPORT_AI_API_KEY: مفتاح Gemini للخادم فقط؛ scripts/configure-support-secret.sh يساعد على إدخاله دون طباعته.
ORIN_NOWPAYMENTS_API_KEY + ORIN_NOWPAYMENTS_IPN_SECRET: مطلوبان لتفعيل الإيداع والتحقق من IPN؛ هذا لا ينفذ السحب تلقائيًا.
ORIN_MAIL_API_KEY + ORIN_EMAIL_CODE_SECRET + ORIN_MAIL_FROM: مطلوبات مسار رمز التسجيل بالبريد. التنفيذ الحالي يستخدم Resend ويحتاج مرسلًا معتمدًا. Firebase Auth التقليدي لا يغني تلقائيًا عن هذا المسار.
GeoIP محلي موثوق أو مزود موثوق مطلوب إذا أردت مدينة/دولة تقريبية؛ غير موصول حاليًا.
قوالب handoff/environment/ لا تحتوي أسرارًا ولا تصلح للتفعيل بمجرد نسخها دون استكمال الإعداد.

10) لوحة إدارة المسؤول
المسار المقصود: /admin. المصدر موجود، لكن هذا التسليم لا يثبت تفعيل حساب Super Admin في الإنتاج أو نجاح كلمة مرور خاصة به.
الوثائق السابقة ذكرت البريد salmamacit.1@gmail.com كهدف مطلوب؛ يجب أن يؤكد المالك صاحب الحساب المطلوب قبل منح صلاحيات. لا توجد كلمة مرور إدارية مشتركة أنشأناها.
سكريبت firebase-functions/scripts/bootstrap-control-admin.mjs يعمل افتراضيًا بوضع فحص جاف ويطلب هوية موجودة مؤكدة. لا يستخدم لتجاوز التحقق.
ملاحظة ترحيل مهمة: قائمة القواعد المقبولة في هذا السكربت تشير إلى ملفات firebase-control القديمة، وليس ملف firebase-security-160.rules. يجب مراجعة توافق bootstrap مع القواعد الصارمة واعتماد القاعدة المراجعة قبل تشغيله في هذا المسار؛ لا تلغِ فحص hash أو تستخدم قواعد أضعف لتمرير السكربت.
اختبر حساب عميل عادي مرفوض من الإدارة، وصلاحيات الموظفين، التجميد/الحظر وإبطالهما، وسجل التدقيق. تعديل الأرصدة يمر بالعملية الموثقة وليس كتابة مباشرة في المحفظة.

11) قاعدة البيانات والنسخ الاحتياطية
نعم: توجد تعريفات البيانات والأنواع والقواعد والفهارس ومخطط SQL والترحيلات في المصدر.
لا: لا تحتوي هذه الحزمة dump لبيانات عملاء Firebase أو Auth. لم يكن تصدير إنتاج كامل متاحًا في هذا العمل، ولا يجوز تسمية القواعد «الداتا بيز كاملة بالعملاء».
المسار الحالي يستخدم Firestore؛ ملفات drizzle/*.sql لمسار SQL آخر، فلا تُنفذها على Firestore أو تعتبرها بيانات المستخدمين.
على المبرمج استخدام وصول المالك المصرح به لأخذ تصدير Firestore، وتصدير Firebase Authentication منفصلًا عند الحاجة. تصدير Firestore لا يتضمن حسابات Authentication أو أسرار Secret Manager أو إعدادات IAM/Hosting تلقائيًا.
خدمة Firestore managed export تتطلب فوترة/Blaze وحاوية Cloud Storage وصلاحيات مناسبة؛ نفّذ التصدير إلى وجهة يملكها المالك، وليس إلى حاوية عامة. اختبر الاستعادة في مشروع منفصل قبل لمس الإنتاج.
لا تُرفق بيانات العملاء أو تصدير Auth بمستودع كود. handoff/DATABASE-CONTENTS.txt يوضح ملفات المخطط والقواعد المرفقة.

لا توجد ضمانة أن تغييرًا لاحقًا لن يسبب مشكلة؛ المحافظة على هذه النسخة كمرجع، ومراجعة الفروقات واختبار التحديث قبل نشره هي طريقة تقليل المخاطر.
